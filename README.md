<h1 align="center">GWM Jolion для Home Assistant</h1>

<p align="center">
  Неофициальная интеграция Home Assistant для Haval Jolion с российской телематикой GWM Cloud.
</p>

> [!WARNING]
> Проект не связан с Great Wall Motor, HAVAL или официальным приложением GWM. Используется неофициальный облачный API. Текущая версия — **0.1.0-alpha.19.3**.

## Возможности

Интеграция получает данные автомобиля из российского GWM Cloud и создаёт стандартные сущности Home Assistant.

### Телеметрия

- двигатель;
- центральный замок;
- двери, окна и багажник;
- пробег;
- топливо в литрах и процентах;
- запас хода;
- давление и температура шин;
- GPS;
- T-Box online/offline и raw-уровень GSM;
- климат;
- уровень масла GWM;
- подогревы передних сидений raw;
- диагностические raw-коды и Protocol Capture.

### Удалённое управление

Поддерживаются запуск/остановка двигателя, замок, багажник, климат, закрытие/экспериментальное открытие окон, flash/horn, обогрев руля, заднего стекла, передний defrost, панорама/шторка и принудительное обновление данных. Набор функций зависит от комплектации и часть comfort-команд остаётся экспериментальной.

Удалённые команды физически меняют состояние автомобиля. Используйте их только в безопасных условиях.

## Встроенные карточки

Интеграция автоматически регистрирует две Lovelace-карточки.

### Основная карточка

```yaml
type: custom:gwm-jolion-card
```

Основная карточка показывает телеметрию, управление, климат, шины, T-Box/GSM, GPS и диагностические состояния. У неё есть собственный визуальный редактор Home Assistant.

### Карточка-пульт

```yaml
type: custom:gwm-jolion-remote-card
```

Начиная с **0.1.0-alpha.19.3** карточка-пульт получила новую SVG-сцену автомобиля **вид сверху**:

- капот расположен слева, багажник справа;
- левая сторона автомобиля соответствует водительской стороне;
- кузов мягко подсвечивается по состоянию замка: закрыт / разблокирован / нет данных;
- в правом верхнем углу показываются T-Box **Online / Offline** и 4-сегментный GSM-индикатор;
- под автомобилем находятся компактные уведомления: двигатель, климат, топливо, пробег, двери, окна и багажник;
- двери анимируются индивидуально по подтверждённым door binary sensors;
- открытый багажник визуально отводится от кузова;
- работающий двигатель даёт мягкую пульсацию моторного отсека;
- включённый климат показывает анимированные потоки воздуха в салоне;
- водительское переднее окно использует подтверждённую шкалу `2210001`: `1=закрыто`, `3=частично открыто`, `2=полностью открыто`;
- для остальных окон до завершения физической привязки кодов карточка не угадывает конкретное стекло, а показывает общий сигнал открытых окон;
- для фар уже подготовлен отдельный SVG/CSS-слой, но он **не активируется**, пока физическим тестом не подтверждён telemetry-код света;
- капот пока статичен: отдельный подтверждённый сигнал его состояния ещё не найден.

Пример:

```yaml
type: custom:gwm-jolion-remote-card
controls:
  - lock
  - engine
  - climate
  - trunk
  - windows
  - refresh
info:
  - range
  - tires
statuses:
  - engine
  - climate
  - fuel
  - mileage
  - doors
  - windows
  - trunk
car_color: "#7c8489"
```

На мобильном экране нижние уведомления автоматически переходят в компактный режим с иконками.

## Подтверждённые данные полевых тестов alpha.19.3

### Подогрев передних сидений

Для обоих передних сидений принята одна шкала:

```text
0 = выключен
1 = минимальный
2 = средний
3 = максимальный
```

Коды:

- `2220001` — водительское сиденье;
- `2220002` — пассажирское сиденье.

Значения `leftFrontSeat` / `rightFrontSeat` из `vehicleBasicsInfo` являются сохранёнными preset/config значениями и **не используются** как fallback живого состояния подогрева. Если live-код `2220001/2220002` отсутствует, соответствующий live sensor остаётся недоступным.

### Окна

Полевой capture показал, что стеклоподъёмники не являются бинарными `0/1`.

Для `2210001`, физически подтверждённого как переднее левое / водительское окно:

```text
1 = закрыто
3 = частично открыто
2 = полностью открыто
```

Для всех `2210001..2210004` binary-состояние теперь декодируется консервативно:

- `1` → закрыто;
- `2` или `3` → окно не закрыто;
- другие значения → неизвестно.

Точное физическое соответствие `2210002..2210004` конкретным оставшимся окнам ещё проверяется, поэтому карточка не приписывает им новые позиции без полевого подтверждения.

### Двигатель и ACC

Для `2016001` подтверждено:

- `0` — двигатель не работает;
- `2` — двигатель работает;
- значение `1` пока не наблюдалось.

ACC будит телематику автомобиля, но в проведённом тесте `2016001` оставался `0`. Отдельная сущность ACC пока не создаётся.

## Карта Home Assistant

Интеграция создаёт `device_tracker` **Местоположение**. Пример:

```yaml
type: map
entities:
  - entity: device_tracker.<ваша_сущность_местоположения>
hours_to_show: 24
```

Точные координаты не включаются в Protocol Capture и скачиваемую диагностику.

## Установка через HACS

1. Откройте HACS → Custom repositories.
2. Добавьте `https://github.com/IndeecDen/ha-gwm-jolion` как **Integration**.
3. Установите GWM Jolion.
4. Полностью перезапустите Home Assistant.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию → GWM Jolion**.

## Ручная установка

Скопируйте каталог `custom_components/gwm_jolion` в `/config/custom_components/gwm_jolion`, затем полностью перезапустите Home Assistant.

## Настройка

Для российского GWM Cloud используются телефон и пароль аккаунта. PIN безопасности нужен только для команд, которые его требуют. По умолчанию polling выполняется каждые 300 секунд.

В **GWM Jolion → Настроить** можно включать/отключать опциональное оборудование и временно включить **Режим поиска GWM-кодов (JSONL-журнал)**.

## Protocol Capture

При включённом режиме поиска кодов создаётся JSONL-сессия в:

```text
/config/gwm_jolion_protocol_capture/gwm_code_search_*.jsonl
```

Сервис метки:

```yaml
action: gwm_jolion.add_capture_marker
data:
  label: WINDOW_FL_FULL
```

Метка ничего не меняет в машине — она только создаёт временную точку в журнале. Правильный полевой порядок: выставить физическое состояние → поставить метку → нажать **Обновить данные**.

Стандартная диагностика сохраняет первый baseline и до 5000 последних refresh-записей; полный JSONL на диске не обрезается. Диагностику нужно скачивать **пока Protocol Capture ещё включён**.

Protocol Capture не сохраняет VIN, точные координаты, телефон/аккаунт, пароли, PIN, access token, IMSI/ICCID и device/vehicle identifiers.

## Поддерживаемые автомобили

Основная разработка и физические тесты выполняются на **Haval Jolion 2022 Premium 2WD** с российской телематикой GWM. Другие Jolion с совместимой телематикой могут работать, но набор функций зависит от комплектации и версии облачного протокола.

## Статус проекта

Проект находится в alpha. Неизвестные GWM-коды не получают пользовательское назначение без физического подтверждения. См. `PROTOCOL.md`, `ROADMAP.md` и GitHub Releases.
