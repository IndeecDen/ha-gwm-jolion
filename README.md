<h1 align="center">GWM Jolion для Home Assistant</h1>

<p align="center">
  Неофициальная интеграция Home Assistant для автомобилей Haval Jolion с российской телематикой GWM Cloud.
</p>

> [!WARNING]
> Проект не связан с Great Wall Motor, HAVAL или официальным приложением GWM. Используется неофициальный облачный API. Текущая версия — **0.1.0-alpha.19.7**.

## Возможности

Интеграция получает данные автомобиля из российского GWM Cloud и создаёт стандартные сущности Home Assistant.

### Телеметрия

- состояние двигателя;
- центральный замок;
- двери, окна и багажник;
- пробег;
- остаток топлива в литрах и процентах;
- запас хода;
- давление и температура всех четырёх шин;
- GPS;
- статус T-Box и уровень GSM;
- состояние климата;
- уровень масла GWM;
- время последнего успешного обновления.

### Удалённое управление

Поддерживаются запуск/остановка двигателя, замок, багажник, окна, климат, flash/horn, обогрев руля, заднего стекла, передний defrost, панорама/шторка и другие экспериментальные comfort-команды. Набор функций зависит от комплектации автомобиля.

### Надёжность удалённых команд

- одновременно выполняется только одна удалённая команда GWM;
- пока команда выполняется, остальные управляющие кнопки временно блокируются;
- перед remote start выполняется свежая проверка двигателя, замка, дверей и багажника;
- явная ошибка GWM завершает ожидание сразу;
- неизвестные состояния не отображаются как ложные `выключено / закрыто / offline`;
- при проблеме авторизации Home Assistant может запросить повторный вход без удаления интеграции.

## Встроенные карточки

Интеграция автоматически регистрирует две Lovelace-карточки.

### Основная карточка

```yaml
type: custom:gwm-jolion-card
```

<p align="center">
  <img src="docs/card.png" alt="GWM Jolion Lovelace card">
</p>

Основная карточка автоматически находит сущности автомобиля и отображает двигатель, замок, двери, окна, багажник, климат, топливо, запас хода, пробег, шины, T-Box, GPS и доступные comfort-функции. Начиная с `0.1.0-alpha.16` у неё есть visual editor Home Assistant.

Для известных модификаций Jolion карточка определяет `2WD / 4WD`.

### Карточка-пульт

```yaml
type: custom:gwm-jolion-remote-card
```

#### `0.1.0-alpha.19.7` — field-tested windows + protocol

В `alpha.19.7` сохранён широкий SUV top-view из `alpha.19.6`, а recovered JSONL marker-тест закрепил физическую привязку всех четырёх окон. Карточка теперь получает raw/binary состояния каждого стекла отдельно и может визуально отражать FR/RR/FL/RL без догадок о позиции.

Ориентация остаётся зафиксированной:

```text
капот слева
багажник справа

верх сцены = правая сторона автомобиля
низ сцены  = левая сторона автомобиля

FR = передняя правая = сверху спереди
RR = задняя правая   = сверху сзади
FL = передняя левая  = снизу спереди
RL = задняя левая    = снизу сзади

ось петель каждой SVG-двери = её левая кромка
FR/RR открываются наружу вверх
FL/RL открываются наружу вниз
```

Визуализация карточки:

- широкий top-view кузов с более SUV-подобными пропорциями;
- отдельные слои четырёх дверей и независимые door-анимации;
- отдельная анимация багажника справа;
- оранжевая пульсация моторного отсека при работающем двигателе;
- вращающийся вентилятор и синие воздушные потоки при включённом климате;
- T-Box **Онлайн / Оффлайн** и 4-сегментный GSM-индикатор справа сверху;
- все четыре окна физически закреплены: `2210001=FL`, `2210002=FR`, `2210003=RL`, `2210004=RR`;
- `2210001` использует полностью пойманную шкалу `1=закрыто`, `3=частично`, `2=полностью открыто`; для остальных окон в recovered run надёжно пойманы `1=closed` и `2=full open`, а generic binary logic по-прежнему безопасно считает `2/3` «не закрыто»;
- raw-состояния всех четырёх окон доступны как diagnostic sensors и используются соответствующими SVG-стёклами карточки;
- фары не связаны с двигателем: `2204008` теперь документирован только как кандидат дальнего света после `LIGHT_HIGH`, без автоматической активации до повторной проверки;
- капот остаётся статическим до обнаружения достоверного hood-status.

#### Статусные плитки

По умолчанию под автомобилем отображаются восемь плиток:

- Двигатель;
- Климат;
- Топливо;
- Пробег;
- Двери;
- Окна;
- Багажник;
- Замок.

В `alpha.19.6` они **всегда содержат текстовое значение**, а не только иконку. Например:

```text
Топливо
42 L

Пробег
12 345 km

Двигатель
Выключен
```

Основная раскладка статусов — **4×2**. Благодаря этому даже на узкой карточке для значения остаётся отдельная ширина. На совсем маленьком контейнере раскладка автоматически становится 2-колоночной. Для статусов больше не используется однострочное обрезание значения.

В visual editor также можно добавить отдельный статус `Defrost`.

#### Кнопки управления

Статусы и controls разделены визуально. Кнопки управления находятся отдельным нижним рядом. По умолчанию это:

- замок;
- двигатель;
- климат;
- багажник;
- обновление.

Дополнительно можно включить окна, обогрев руля, заднего стекла, передний defrost, панораму и шторку.

Пример ручной YAML-настройки:

```yaml
type: custom:gwm-jolion-remote-card
controls:
  - lock
  - engine
  - climate
  - trunk
  - windows
  - refresh
info: []
statuses:
  - engine
  - climate
  - fuel
  - mileage
  - doors
  - windows
  - trunk
  - lock
car_color: "#74808b"
```

Настройки оборудования интеграции имеют приоритет: если функция отключена в **GWM Jolion → Настроить**, карточка не показывает соответствующее управление.

Компоновка второй карточки вдохновлена идеей `lovelace-starline-card`, но код, CSS и автомобильная SVG-графика реализованы отдельно; сторонние assets в проект не копировались.

### Полевые уточнения alpha.19.3+

Для обоих передних сидений принята одинаковая live-шкала:

```text
2220001 = водительское
2220002 = пассажирское

0 = выключен
1 = минимальный
2 = средний
3 = максимальный
```

`vehicleBasicsInfo.leftFrontSeat/rightFrontSeat` являются preset/config значениями и не используются как fallback живого подогрева.

Окна используют консервативную multistate-логику:

```text
1 = закрыто
2/3 = окно не закрыто
остальные значения = unknown
```

Физическая привязка окон теперь подтверждена marker-тестом: `2210001=переднее левое/водительское`, `2210002=переднее правое`, `2210003=заднее левое`, `2210004=заднее правое`. Для `2210001` отдельно пойманы `1=закрыто`, `3=частично`, `2=полностью открыто`; для `2210002..2210004` в recovered run надёжно пойманы `1=закрыто` и `2=полностью открыто`, а `3` не успело попасть в отдельный poll.

### Автомобиль на карте Home Assistant

Интеграция создаёт GPS-сущность **Местоположение** (`device_tracker`). Её можно добавить в стандартную карточку Home Assistant `map`:

```yaml
type: map
entities:
  - entity: device_tracker.<ваша_сущность_местоположения>
hours_to_show: 24
```

Точные координаты используются только GPS-сущностью и не попадают в Protocol Capture или скачиваемую диагностику.

## Установка через HACS

1. Откройте **HACS**.
2. Перейдите в **⋮ → Custom repositories**.
3. Добавьте репозиторий:

```text
https://github.com/IndeecDen/ha-gwm-jolion
```

4. Выберите тип **Integration**.
5. Установите **GWM Jolion**.
6. Полностью перезапустите Home Assistant.
7. Откройте **Настройки → Устройства и службы → Добавить интеграцию**.
8. Найдите **GWM Jolion** и выполните настройку.

## Ручная установка

Скопируйте каталог `custom_components/gwm_jolion` в `/config/custom_components/gwm_jolion` и полностью перезапустите Home Assistant.

## Настройка

Для подключения используются номер телефона и пароль российского приложения GWM. PIN безопасности нужен только для удалённых команд, которые его требуют.

По умолчанию polling выполняется каждые **300 секунд**. В **Настройки → Устройства и службы → GWM Jolion → Настроить** можно изменить polling, remote controls и указать опциональное оборудование: панораму/шторку, обогрев руля, стекол, сидений, Cabin Clean и очиститель воздуха.

Там же можно временно включить **Режим поиска GWM-кодов (JSONL-журнал)**.

## Поддерживаемые автомобили

Основная разработка и тестирование выполняются на **Haval Jolion 2022 Premium** с российской телематикой GWM. Другие совместимые комплектации Jolion могут работать, но набор функций зависит от автомобиля.

## Безопасность

Удалённые команды физически меняют состояние автомобиля. Используйте запуск двигателя, климат, замки, окна и другие команды только в безопасных условиях. Интеграция не заменяет штатные системы безопасности автомобиля.

## Диагностика

Обычный debug-журнал:

```yaml
logger:
  logs:
    custom_components.gwm_jolion: debug
```

### Protocol Capture — поиск GWM-кодов

Начиная с `0.1.0-alpha.18` интеграция может вести отдельную JSONL-сессию в:

```text
/config/gwm_jolion_protocol_capture/gwm_code_search_*.jsonl
```

При каждом setup/reload с включённым capture создаётся новый timestamped JSONL-файл. **Обновление или перезагрузка интеграции не удаляет старые capture-файлы**. Стандартная диагностика экспортирует текущую активную сессию, а предыдущие тесты можно забрать напрямую из этого каталога.

Каждый успешный опрос сохраняет безопасный raw snapshot, изменения `previous → value`, неизвестные коды и источник обновления. Schema 2 дополнительно сохраняет `signal_units`, `signal_item_seen_keys`, безопасные `status_meta`, `status_structure`, `vehicle_basics_structure`, `tbox_meta` и `tbox_structure`.

Автоматические capture-записи не включают VIN, точные координаты, телефон/аккаунт, пароль, PIN, access token, IMSI/ICCID, vehicle ID и другие идентификаторы.

### Метки этапов теста

```yaml
action: gwm_jolion.add_capture_marker
data:
  label: WINDOW_FL_FULL
```

Метка записывается отдельной JSONL-строкой `type=marker` и не ломает telemetry baseline. Максимальная длина — 80 символов.

Рекомендуемая последовательность теста:

1. выставить одно физическое состояние;
2. добавить метку;
3. нажать **Обновить данные**;
4. перейти к следующему состоянию.

### Итоговая диагностика одной сессии

Пока Protocol Capture включён:

1. выполните финальное **Обновить данные**;
2. скачайте стандартную диагностику Home Assistant;
3. только после этого отключите capture.

Экспорт сохраняет первый telemetry baseline + до 5000 самых свежих корректных записей. Полный JSONL-файл на диске не обрезается.
