<h1 align="center">GWM Jolion для Home Assistant</h1>

<p align="center">
  Неофициальная интеграция Home Assistant для Haval Jolion с российской телематикой GWM Cloud.
</p>

> [!WARNING]
> Проект не связан с Great Wall Motor, HAVAL или официальным приложением GWM. Используется неофициальный облачный API. Текущая версия — **0.1.0-alpha.20**.

## Что изменилось в alpha.20

`0.1.0-alpha.20` — cleanup-релиз пользовательского интерфейса интеграции. После полевых тестов raw-коды больше не создают десятки отдельных сущностей Home Assistant.

При обновлении существующей установки выполняется миграция Entity Registry:

- удаляются TPMS raw/status, window raw/window learn, light raw, служебные vehicleBasics/model/service entities и вспомогательные diagnostic entities;
- удаляются дублирующие `Открыть двери` / `Закрыть двери` — для этого теперь используется стандартная `lock`-сущность;
- удаляются кнопки физически неподтверждённых/экспериментальных команд окон, панорамы, шторки, front defrost и Cabin Clean;
- индивидуальные окна пересоздаются как обычные пользовательские binary sensors, а не diagnostics;
- подогревы передних сидений остаются как полезные status sensors с чистыми названиями;
- raw-данные **не теряются**: они продолжают храниться во внутреннем state, Protocol Capture и стандартной диагностике, а нужные карточкам raw-значения передаются через attributes существующих сущностей.

Это намеренно breaking cleanup для alpha-ветки. Если автоматизация напрямую использовала удалённый raw entity, её нужно перевести на соответствующую нормальную сущность или Protocol Capture.

## Пользовательские сущности

### Телеметрия

В обычном Entity Registry остаются только полезные данные:

- `Запас хода`;
- `Топливо` в литрах;
- `Уровень топлива` в процентах;
- `Пробег`;
- давление всех четырёх шин;
- температура всех четырёх шин;
- `Подогрев сиденья водителя` — уровень `0..3`;
- `Подогрев сиденья пассажира` — уровень `0..3`;
- `Последнее обновление GWM` — единственный оставшийся diagnostic timestamp.

### Состояния

Создаются binary sensors:

- T-Box online/offline;
- двигатель работает / выключен;
- общий статус дверей;
- передняя левая дверь;
- передняя правая дверь;
- задняя левая дверь;
- задняя правая дверь;
- общий статус окон;
- переднее левое окно;
- переднее правое окно;
- заднее левое окно;
- заднее правое окно;
- багажник;
- климат.

Центральный замок представлен стандартной сущностью `lock`, поэтому отдельный `vehicle_unlocked` binary sensor больше не создаётся. GPS представлен `device_tracker`, поэтому отдельный `gps_authorized` binary sensor также удалён.

### Полезные attributes вместо raw entities

Чтобы не терять данные для карточек и диагностики:

- индивидуальные окна содержат `raw_state`;
- `T-Box онлайн` содержит `signal_level_raw`, `model_code_raw`, `oil_qty_raw`, `gps_available` и настроенные feature flags;
- кнопка `Обновить данные` содержит состояние последней remote-команды и Protocol Capture.

## Удалённое управление

Для обычного пользователя используются стандартные Home Assistant сущности там, где это возможно.

### Native entities

- `lock` — открыть / закрыть автомобиль;
- `climate` — включить / выключить климат и выбрать температуру `16..32 °C`;
- `number` — время работы климата `5..30 мин`.

### Кнопки

При включённом Remote Control и сохранённом PIN создаются только полезные action buttons:

- запустить двигатель;
- остановить двигатель;
- моргнуть фарами;
- подать звуковой сигнал;
- моргнуть фарами + подать сигнал;
- открыть багажник;
- закрыть багажник;
- включить / выключить обогрев заднего стекла;
- включить / выключить обогрев руля.

`Обновить данные` создаётся всегда.

### Что намеренно не создаётся как кнопка

- lock/unlock — дублируют native `lock`;
- закрыть окна — cloud payload существует, но в физическом тесте стекла не закрылись;
- открыть окна — experimental;
- открыть/закрыть панораму и шторку — experimental;
- front defrost — отдельный live-status не подтверждён;
- Cabin Clean — experimental.

Низкоуровневые `gwm_jolion.*` services пока сохранены для совместимости и протокольных тестов, но основной пользовательский сценарий строится на native entities и отфильтрованных buttons.

## Подтверждённая телеметрия

Основные полевые соответствия:

```text
2016001 = двигатель: 0 OFF, 2 RUNNING
2208001 = центральный замок: 0 locked, 1 unlocked
2206001 = багажник: 0 closed, 1 open
2202001 = климат: 0 OFF, 1 ON

2210001 = переднее левое / водительское окно
2210002 = переднее правое окно
2210003 = заднее левое окно
2210004 = заднее правое окно
```

Для водительского окна отдельно поймана шкала:

```text
1 = закрыто
3 = частично открыто
2 = полностью открыто
```

Для остальных окон надёжно подтверждены `1=закрыто` и `2=полностью открыто`; generic binary logic консервативно считает `2/3` состоянием «не закрыто».

Подогревы передних сидений:

```text
2220001 = водитель
2220002 = пассажир

0 = выключен
1 = минимальный
2 = средний
3 = максимальный
```

`2204008` остаётся только кандидатом статуса дальнего света: в marker-тесте после `LIGHT_HIGH` был пойман переход `0→1`, но автоматическое включение фар в карточке пока не разрешено.

## Встроенные карточки

Интеграция автоматически регистрирует две Lovelace-карточки.

### Основная карточка

```yaml
type: custom:gwm-jolion-card
```

Основная карточка показывает топливо, запас хода, пробег, состояние автомобиля, климат, шины и основные remote actions. В `alpha.20`:

- исправлена физическая привязка окон на основании marker-теста;
- сломанное управление окнами скрыто, но статус четырёх окон остаётся;
- experimental панорама/front-defrost скрыты из основного UI;
- GSM, model code, feature flags и состояние remote-команды читаются из attributes существующих entities вместо отдельных raw sensors.

### Анимированная карточка-пульт

```yaml
type: custom:gwm-jolion-remote-card
```

Ориентация автомобиля:

```text
капот слева
багажник справа

верх сцены = правая сторона автомобиля
низ сцены  = левая сторона автомобиля

FR = передняя правая = сверху спереди
RR = задняя правая   = сверху сзади
FL = передняя левая  = снизу спереди
RL = задняя левая    = снизу сзади
```

По умолчанию статусные плитки:

- Двигатель;
- Климат;
- Топливо;
- Пробег;
- Двери;
- Окна;
- Багажник;
- Замок.

В `alpha.20` карточка продолжает получать raw window level через attribute `raw_state`, поэтому удаление четырёх raw window sensor entities не ломает анимацию стекол. Замок читается из native `lock`, GSM — из T-Box attribute.

Безопасный набор controls в visual editor:

- замок;
- двигатель;
- климат;
- багажник;
- обновление;
- обогрев руля;
- обогрев заднего стекла.

Пример:

```yaml
type: custom:gwm-jolion-remote-card
controls:
  - lock
  - engine
  - climate
  - trunk
  - refresh
statuses:
  - engine
  - climate
  - fuel
  - mileage
  - doors
  - windows
  - trunk
  - lock
car_color: "#74808b"
```

## Установка через HACS

1. Откройте **HACS**.
2. Перейдите в **⋮ → Custom repositories**.
3. Добавьте:

```text
https://github.com/IndeecDen/ha-gwm-jolion
```

4. Тип — **Integration**.
5. Установите **GWM Jolion**.
6. Полностью перезапустите Home Assistant.
7. Откройте **Настройки → Устройства и службы → Добавить интеграцию**.
8. Найдите **GWM Jolion**.

## Ручная установка

Скопируйте каталог `custom_components/gwm_jolion` в `/config/custom_components/gwm_jolion` и полностью перезапустите Home Assistant.

## Настройка

Для подключения используются номер телефона и пароль российского приложения GWM. PIN безопасности нужен для удалённых команд.

По умолчанию polling выполняется каждые **300 секунд**. В **GWM Jolion → Настроить** доступны:

- интервал polling;
- Remote Control;
- cooldown между командами;
- PIN безопасности;
- Protocol Capture;
- наличие обогрева руля;
- наличие обогрева заднего стекла;
- status водительского подогрева сиденья;
- status пассажирского подогрева сиденья.

Экспериментальные панорама/front-defrost/Cabin Clean больше не засоряют обычный Options Flow.

## Поддерживаемые автомобили

Основная разработка и тестирование выполняются на **Haval Jolion 2022 Premium** с российской телематикой GWM. Другие совместимые комплектации могут работать, но набор доступных функций зависит от автомобиля.

## Безопасность

Удалённые команды физически меняют состояние автомобиля. Используйте запуск двигателя, климат, замки и другие команды только в безопасных условиях. Интеграция не заменяет штатные системы безопасности автомобиля.

## Диагностика

Обычный debug-журнал:

```yaml
logger:
  logs:
    custom_components.gwm_jolion: debug
```

### Protocol Capture

Режим поиска GWM-кодов пишет отдельные JSONL-сессии в:

```text
/config/gwm_jolion_protocol_capture/gwm_code_search_*.jsonl
```

При каждом setup/reload с включённым capture создаётся новый timestamped файл. **Старые capture-файлы не удаляются при обновлении интеграции.** Стандартная диагностика показывает текущую активную сессию, а предыдущие тесты можно забрать прямо из каталога.

Raw-коды, удалённые из Entity Registry в `alpha.20`, по-прежнему присутствуют в Protocol Capture.

### Метки этапов теста

```yaml
action: gwm_jolion.add_capture_marker
data:
  label: WINDOW_FL_FULL
```

Рекомендуемый тест:

1. выставить одно физическое состояние;
2. добавить marker;
3. нажать **Обновить данные**;
4. дождаться нового cloud snapshot;
5. перейти к следующему состоянию.

Перед обновлением интеграции или выключением capture сначала сохраните нужный JSONL либо скачайте стандартную диагностику. Сам файл после обновления не удаляется, но новая загрузка интеграции начнёт новую capture-сессию.
