# Changelog

## 0.1.0-alpha.9

Исправление трактовки поля `oilQty` российского GWM API.

### Исправлено

- `oilQty` больше не трактуется как уровень топлива;
- диагностическая сущность переименована в `Уровень масла GWM (0–8)`;
- в карточке блок `Топливо GWM` заменён на `Масло`;
- уровень масла отображается как 8-сегментная шкала без вычисления процентов;
- обычный уровень топлива по-прежнему берётся из фактических литров и объёма бака;
- cache-busting встроенной карточки обновлён до `0.1.0-alpha.9`.

### Обоснование

В реальных ответах GWM `oilQty` не коррелирует с количеством топлива: при баке около 82–84% поле может иметь значение `4`. Российские реализации GWM также используют `oilQty` как уровень масла. Поэтому в этой версии поле отделено от топливной телеметрии.

## 0.1.0-alpha.8

Компактная карточка, подробный статус окон и графические индикаторы системы.

### Карточка

- заголовок теперь всегда одной строкой и одним шрифтом: модель + имя автомобиля из GWM API + `2WD` / `4WD`, например `Haval Jolion Жулик 2WD`;
- удалена крупная декоративная иконка автомобиля;
- верхняя статистика стала компактной сеткой `Топливо л / Топливо % / Запас / Пробег`;
- кнопка `Окна` показывает конкретно открытые окна: переднее левое, переднее правое, заднее левое, заднее правое;
- подтверждена привязка телеметрии окон: `2210002` = переднее левое, `2210001` = переднее правое, `2210004` = заднее левое, `2210003` = заднее правое;
- при наличии открытого окна кнопка закрывает все окна;
- когда все окна закрыты, кнопка отправляет экспериментальную команду открытия всех окон;
- на кнопке `Обновить` показывается давность последнего успешного опроса GWM (`только что`, `N мин назад`, `N ч назад`);
- в разделе `Система` уровень GSM отображается графическими делениями вместо raw-числа;
- `oilQty` отображается как 8-сегментная шкала топлива GWM.

### Протокол

- добавлен экспериментальный сервис `open_windows` (`0x08`, `switchOrder=1`, четыре окна со значением `10`);
- команда закрытия окон остаётся подтверждённой и не изменена.

### Уточнение `oilQty`

- прежнее название `Уровень масла (raw)` было ошибочным;
- по открытым реализациям GWM `oilQty` — это не уровень моторного масла, а штатная шкала топлива `0–8` делений;
- поэтому сущность переименована в `Шкала топлива GWM (0–8)` и в карточке не выдаётся за уровень масла двигателя.

## 0.1.0-alpha.7

Версионирование HACS и доработка встроенной Lovelace-карточки.

### HACS / релизы

- добавлен GitHub Actions workflow, который создаёт GitHub Release и tag по версии из `manifest.json`;
- HACS теперь получает человекочитаемую версию (`0.1.0-alpha.7`, далее `alpha.8` и т. д.) вместо SHA коммита;
- релиз создаётся только для коммита, сообщение которого начинается с текущей версии, либо при ручном запуске workflow.

### Карточка

- убран принудительный заголовок `Haval Jolion`;
- в заголовке используется имя автомобиля из GWM, которое уже попадает в Home Assistant Device (`vehicleName`), рядом выводится `2WD` / `4WD`;
- модель `Haval Jolion` выводится второй строкой только если она не дублирует имя автомобиля;
- панорама и шторка перенесены непосредственно в раздел `Управление`;
- для панорамы теперь одна кнопка открыть/закрыть, для шторки — одна кнопка открыть/закрыть;
- так как подтверждённой телеметрии положения панорамы/шторки пока нет, при первом нажатии карточка просит выбрать `открыть` или `закрыть`, после успешной команды переключает действие локально до перезагрузки страницы;
- кнопка окон больше не выглядит отключённой, когда окна закрыты;
- если окна закрыты, нажатие объясняет, что подтверждена только команда закрытия; неподтверждённая команда открытия не отправляется;
- cache-busting URL карточки обновлён до `0.1.0-alpha.7`.

## 0.1.0-alpha.6

Обновление встроенной Lovelace-карточки и её отображения комплектации без изменения payload подтверждённых команд.

### Карточка

- рядом с `Haval Jolion` автоматически отображается `2WD` или `4WD`, когда код модификации известен;
- для российских модификаций Jolion используется подтверждённая карта: `CC7150BA00B` / `CC7150BA01B` → `2WD`, `CC7150BA24C` → `4WD`;
- добавлен блок управления панорамой: открыть / закрыть;
- добавлен блок управления шторкой панорамы: открыть / закрыть;
- команды панорамы и шторки помечены как экспериментальные, так как обратный статус положения пока не расшифрован;
- подогрев сидений и электрообогрев лобового остаются status-only: карточка явно показывает, что управляющий payload пока не подтверждён;
- сохранено управление закрытием окон;
- cache-busting URL карточки обновлён до `0.1.0-alpha.6`.

### Версионирование

- сообщения коммитов для релизных изменений начинаются с номера версии (`0.1.0-alpha.6`, далее `alpha.7` и т. д.); короткий SHA GitHub остаётся внутренним идентификатором коммита.

## 0.1.0-alpha.5

Обновление встроенной Lovelace-карточки без изменения протокола подтверждённых remote-команд.

### Карточка

- в верхнюю статистику добавлен `Топливо %`;
- подпись количества топлива изменена на `Топливо л`;
- убраны постоянные status chips `Закрыт`, `Двигатель ...`, `Климат ...`; предупреждения об открытых дверях, окнах и багажнике сохранены;
- удалён отдельный блок `Автомобиль`;
- в блок `Управление` добавлен таймер автозапуска двигателя 5–30 минут;
- выбранное время передаётся существующему сервису `gwm_jolion.start_engine` как `operation_time`;
- управление кондиционером перенесено в блок `Климат`;
- в блок `Климат` добавлены обогрев руля, обогрев заднего стекла и экспериментальный обдув лобового;
- статусы подогрева водительского/пассажирского сидений и электрообогрева лобового отображаются без управляющих команд, пока payload этих функций не подтверждён;
- обновлён cache-busting URL встроенной карточки.

### Безопасность

- для сидений и электрообогрева лобового карточка не отправляет неподтверждённые GWM-команды.

## 0.1.0-alpha.4

Безопасное обновление телеметрии и диагностики. Встроенная `gwm-jolion-card` и remote payloads не изменялись.

### Добавлено

- нормализованная модель `Haval Jolion` вместо внутреннего имени `HavalA01_...`;
- вычисляемый процент топлива по фактическим литрам и объёму бака;
- диагностические сенсоры двигателя, объёма бака, конфигурации, типа автомобиля, телематической платформы и raw-кода модели;
- диагностический сенсор состояния `vehicleBasicsInfo`;
- безопасная структура ответа `vehicleBasicsInfo` без значений, VIN, координат и других приватных данных;
- unit tests для нормализации модели, расчёта топлива и безопасного описания структуры ответа.

### Изменено

- ошибки GWM API теперь могут сохранять код ответа для диагностики;
- `vehicleBasicsInfo` различает `success_with_data`, `success_empty`, `unsupported` и `error`;
- информация автомобиля из `acquireVehicles` приводится к стабильным пользовательским полям.

## 0.1.0-alpha.3

Backend/diagnostics release. Встроенная `gwm-jolion-card` не изменялась.

### Добавлено

- безопасная диагностика Home Assistant с автоматическим удалением VIN, телефона, PIN, пароля, token, IMSI/ICCID и координат;
- история неизвестных GWM telemetry codes;
- счётчик неизвестных кодов как diagnostic sensor;
- время последнего успешного обновления GWM как timestamp sensor;
- безопасный whitelist snapshot `vehicleBasicsInfo`;
- informational capability framework для комплектаций Jolion;
- dependency-free protocol registry;
- четыре диагностических binary sensor для окон `2210001–2210004` без неподтверждённой привязки к физической позиции;
- `services.yaml` для всех зарегистрированных действий;
- английские переводы config/services;
- `PROTOCOL.md`;
- unit tests для protocol/capabilities;
- GitHub Actions: HACS validation, hassfest, compile/JSON/YAML/tests.

### Изменено

- удалённые команды дополнительно защищены lock от одновременного выполнения;
- последняя команда сразу получает состояние `pending` во время ожидания результата;
- `vehicleBasicsInfo` по-прежнему необязателен и не ломает основной polling при ошибке.

### Не изменялось

- frontend-файл `gwm-jolion-card.js`;
- payload существующих подтверждённых команд;
- climate payload;
- существующие unique IDs основных сущностей.
