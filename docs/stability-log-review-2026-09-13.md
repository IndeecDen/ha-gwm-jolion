## Исправления по результатам проверки кода

- HTTP 401 обрабатывается даже при не-JSON ответе; HTTP 429/5xx, тайм-ауты и повреждённые ответы считаются временными сбоями.
- Обновление токена сериализовано с проверкой токена отклонённого запроса: параллельные запросы используют уже обновлённую сессию.
- Отказ обновлённой сессии после успешного входа допускает следующую попытку опроса; явный отказ входа по-прежнему требует исправления авторизации.
- Цикл обновления ограничен 120 секундами. При ошибке сохраняются тип, код, время и число последовательных неудач; сообщения ответов, токены и идентификаторы в новую запись ошибки не включаются.
- При включённой записи протокола ошибки добавляются как `refresh_error`. Диагностика содержит `coordinator.update_health` с последней ошибкой и длительностью попытки.
- Поиск сущностей в обеих карточках ограничен по времени и повторяется после сбоя. Запоздавший ответ для ранее выбранного автомобиля не закрепляется за новым автомобилем.
- Ожидание сервиса в карточке ограничено; тайм-аут снимает локальное ожидание, но не повторяет и не отменяет команду автомобиля. Её результат может оставаться неизвестным.
- Перед запуском двигателя выполняется непосредственное обновление; при неуспехе запуск блокируется. Прерванное ожидание команды не оставляет статус `pending`.

## Проверка на установленной системе

Автоматические тесты воспроизводят сетевые и браузерные сбои на подставных ответах. Они не доказывают устранение конкретной остановки, наблюдавшейся на автомобиле.

После установки версии 0.1.0-beta.6 нужно оставить интеграцию работать не менее 48 часов с записью протокола. При повторении сбоя сохранить JSONL, стандартную диагностику интеграции и запись из системного журнала Home Assistant за соответствующее время. Отдельно проверить возвращение карточки после потери соединения с Home Assistant. Физические команды во время разработки не отправлялись.
