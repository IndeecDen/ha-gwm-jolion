# GWM Jolion — Roadmap

Актуальная версия: **0.1.0-alpha.19.3**.

Проект развивается по принципу: пользовательские значения и remote-команды добавляются только после физического подтверждения на автомобиле или после достаточного набора безопасных диагностических данных.

## Готово

### Базовая интеграция

- российский GWM Cloud login;
- polling автомобиля;
- стандартные HA-сущности;
- удалённый запуск/остановка двигателя;
- замок, багажник, климат;
- шины, топливо, пробег, запас хода;
- GPS device_tracker;
- T-Box online/offline и GSM raw;
- diagnostics и reauth;
- feature flags комплектации;
- две встроенные Lovelace-карточки.

### Protocol Capture

- JSONL capture-сессии;
- baseline + diff;
- ручные marker-записи;
- schema 2: units, item keys, status meta, T-Box meta, структуры без значений;
- стандартная диагностика: первый baseline + до 5000 последних refresh-записей;
- полный JSONL без ограничения на диске;
- privacy redaction VIN/coordinates/account/credentials/device identifiers.

### 0.1.0-alpha.19.3

#### Remote card

- новый SVG автомобиля вид сверху;
- капот слева, багажник справа;
- подсветка кузова по locked/unlocked;
- Online/Offline + 4-сегментный GSM в правом верхнем углу;
- компактные статусы двигателя, климата, топлива, пробега, дверей, окон и багажника;
- индивидуальная анимация дверей по существующим door binary sensors;
- анимация открытого багажника;
- анимация работающего двигателя;
- анимация климата;
- подтверждённая анимация водительского окна `2210001` (`1 closed`, `3 partial`, `2 full`);
- подготовлен неактивный слой фар без ложной привязки к двигателю;
- капот остаётся статическим до обнаружения подтверждённого telemetry-сигнала.

#### Полевые исправления

- `vehicleBasicsInfo.leftFrontSeat/rightFrontSeat` больше не используются как fallback живого подогрева;
- live seat source: `2220001/2220002`;
- для обоих сидений принята шкала `0 off / 1 low / 2 medium / 3 high`;
- окна больше не считаются бинарными `0/1`;
- generic window binary: `1 = closed`, `2/3 = not closed`, остальные значения unknown;
- `2210001` физически подтверждён как переднее левое / водительское окно;
- позиции `2210002..2210004` остаются без новой физической подписи до marker-теста.

## Следующие физические тесты

### Окна

Подтвердить физическую позицию оставшихся кодов:

- `2210002`;
- `2210003`;
- `2210004`.

Для каждого окна: CLOSED → HALF → FULL → CLOSED, с отдельной marker-записью и refresh после каждого состояния.

После подтверждения:

- добавить точную анимацию всех четырёх стёкол;
- обновить friendly names individual window binary sensors;
- проверить payload удалённого закрытия/открытия всех окон.

### Свет

Marker-тесты:

- LIGHT_OFF;
- LIGHT_AUTO;
- LIGHT_PARKING;
- LIGHT_LOW;
- LIGHT_HIGH.

Кандидаты `2204007` и `2204008` пока не получают назначение без физического подтверждения. После подтверждения включить подготовленную анимацию фар remote-card.

### Состояние автомобиля / ACC

Проверить последовательность:

- VEHICLE_SLEEP;
- DOOR_WAKE;
- IGNITION_ACC;
- ENGINE_RUNNING;
- ENGINE_STOPPED;
- VEHICLE_LOCKED.

Цель: определить, существует ли отдельный telemetry-сигнал ACC/wake и появляется ли когда-либо `2016001 = 1`.

## Следующие программные задачи

### Телеметрия

- telemetry freshness/age по `status_meta.acquisitionTime`;
- точное отображение stale cloud status;
- дополнительный анализ T-Box;
- поиск подтверждённых сигналов света и капота;
- исследование температуры наружного воздуха без назначения неподтверждённых кодов.

### Remote-команды

- повторная проверка payload `0x08` для закрытия/открытия окон;
- не считать успешный cloud response доказательством физического выполнения без последующего telemetry refresh;
- новые command payload не добавлять по догадке.

### Frontend

- после window marker-теста — индивидуальные четыре window animations;
- после light marker-теста — реальные фары/ДХО;
- при появлении hood sensor — анимация капота;
- возможное отображение telemetry freshness прямо в карточке;
- синхронизация internal frontend version всех bundled cards.

### Repository hygiene

- удалить committed `__pycache__`;
- добавить/проверить `.gitignore` для Python cache;
- продолжать HACS/Hassfest/Python CI перед каждым release.

## Правило релизов

Перед публикацией alpha-релиза:

1. code;
2. manifest + internal VERSION;
3. CHANGELOG;
4. ROADMAP;
5. README для пользовательских изменений;
6. tests/CI;
7. merge в `main`;
8. GitHub Release/tag.
